# Changelog

## 0.1.1

Fixes and a new render failure.

- New render failure `BR_SANDBOX_RUNNER_IS_POD_IDENTITY{client,mode,namespace}`: a `runner.service_account` named `sandbox` with a `runner.namespace` that is a sandbox namespace of the installation fails the render. The runner identity must not be the identity of the sandbox pods. Values that passed before with such a pair now fail; any other pair is unchanged.
- New rule `BR_SANDBOX_RUN_AS_NON_ROOT` in the admission policy: every container of a `role=sandbox` pod (`containers`, `initContainers` and `ephemeralContainers`) sets `runAsNonRoot: true` and a `runAsUser` above 0 in its own `securityContext`, and the pod does not share its process namespace. The policy has thirteen rules now. Two exceptions: the seed container, by its name and by its exact tools image (with the mirror prefix), still pinned to root, a read-only root file system and no port; and the pods of the network check, which run as uid 0, by the user name `system:serviceaccount:{system namespace}:br-sandbox-netcheck` (no exception when `network_check.enabled` is false). The policy also watches `UPDATE` of `pods/ephemeralcontainers`.
- The agent container and the init container of the pod template set `runAsNonRoot: true`. A render with `runAsUser` or `runAsGroup` 0 still fails (schema minimum 1).
- The README lists the rule and states that no rule protects the seed against a compromised adapter.
- The README states that a node needs a kubelet with subordinate id ranges for user namespaces, that the chart ships and requires no node label for it, that a node without it refuses the pod at start, and that `pool.node_selector` restricts the pool to prepared nodes.
- The README states that the check of foreign values in the chart files covers registries and host names only, and that a client or project name is checked by review.
- Tests: the size of the pool is checked against the values of the LimitRange (default request, default, max), the six quantities of the ResourceQuota and the six bounds of the size rule of the admission policy, with two sizes. No binding of the render names the `sandbox` service account of a sandbox namespace. `pool.node_selector` reaches the pod. The check of foreign values no longer reads a variable that nothing sets.

## 0.1.0

First release. The chart of the sandbox: one installation per cluster, one namespace per (client, mode).

- Per (client, mode): Namespace (Pod Security `baseline` enforced, `restricted` warn and audit), ResourceQuota (size times `max_sandboxes` + `quota.extra_pods`, plus the resources of the seed container of each sandbox when it is enabled), LimitRange, ServiceAccount `sandbox` without token, the warm pool (ReplicaSet without `spec.replicas`: a value rendered by the chart would be reset at each `helm upgrade`, so the keeper is the only writer of the replica count; a pool starts with one replica until the keeper runs, and `pool.floor` is read by the keeper, not applied by the chart), NetworkPolicies, admission policy and binding, runner Role, ConfigMap `br-sandbox-config`.
- The pod-level seccomp profile is `RuntimeDefault`, and a container that sets its own `seccompProfile` must set `RuntimeDefault` too.
- Modes `none`, `allow`, `full`. `none` has only `default-deny`. `full` opens the public addresses except every internal list. `allow` opens only the pods `br.sandbox/role=proxy` of the egress namespace of the same (client, mode) on the proxy port; namespace and pod are selected in the same rule item. The proxy itself is not rendered yet.
- A (client, mode) that uses a proxy (mode `allow`, and mode `full` with a non-empty `credential_set`) has a second namespace `{sandbox namespace}-egress` for the proxy pods, the credential Secret and the CA key. It carries `br.sandbox/egress=true`, the client and mode labels and the Pod Security labels of the sandbox namespace, and never `br.sandbox/managed`. It holds a default-deny, `ingress-tunnel` (only from the sandbox namespace of the same (client, mode), TCP on `egress.proxy.port`), `egress-proxy` (public addresses except the internal, pod, service, node, node public and load balancer lists) and a ResourceQuota on pods (`egress.quota.pods`, default 4). No identity of the chart has a Role or a RoleBinding there. The name comes from the helper `br-sandbox-chart.egress.namespace`; a name over 63 characters fails with `BR_SANDBOX_NAME_TOO_LONG`.
- Mode `full` with a credential set reaches only the proxy; its pod resolver is `127.0.0.1`. A `credential_set` on mode `none` fails the render with `BR_SANDBOX_CREDENTIAL_SET_MODE`. A runner namespace equal to an egress namespace fails with `BR_SANDBOX_SHARED_NAMESPACE`.
- The admission policy matches every pod of a managed namespace. A pod passes if it is `role=sandbox` and follows rules 1 to 9 and the label rules; any other role is refused, `role=proxy` included.
- The sandbox pod has an init container that copies `bsdtar` and `pause` from `br-sandbox-tools`, and a second root container `seed` (key `tools.seed_container.enabled`) that writes `/skills`, which the agent mounts read-only.
- The network check fails when a class of target has no target (listed targets, node kubelet, node API, API service, DNS service, cluster name, pod IP), with one report line per missing class.
- Once per installation: system Namespace, keeper Deployment, Roles and NetworkPolicies (when `keeper.enabled`), the network check Job and its ClusterRole (when `network_check.enabled`).
- Empty extension points for the egress proxy and the keeper objects: the named templates `br-sandbox-chart.slot.egress.*` and `br-sandbox-chart.slot.keeper.objects`. They render nothing.
- The egress namespaces and their policies render for every mode `allow`, and for mode `full` with a `credential_set`, whatever the value of `egress.enabled`. `egress.enabled: true` lets the `allow` lists and the credential sets pass the validation; it stays `false` until the proxy objects exist, which come with a later change of this chart. The slot `br-sandbox-chart.slot.egress.objects` is called once per egress namespace and receives its name. While `egress.enabled` is false, a non-empty `allow` list or `credential_set` of a mode fails the render with `BR_SANDBOX_EGRESS_DISABLED{client,mode,key}`. While it is true, a non-empty `allow` list in mode `none` or `full` fails with `BR_SANDBOX_ALLOW_MODE{client,mode}`.
- No Secret and no bucket is rendered. No object of the chart says that a response is scrubbed: the proxy has no response scrub.
- Public inputs, documented in the README: `registry_mirror`, `pull_secrets`, `image_pull_policy`, `runtimeClassName`, `runAsUser`, `runAsGroup`, `warm_max_age_seconds`, the per-mode `pool` override, `pool.node_selector`, `keeper.settings`, and the label contract. `values.schema.json` is strict: a key outside its place fails the render.

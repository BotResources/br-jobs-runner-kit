# br-sandbox-keeper

The controller of the sandbox pools of `br-runner-sandbox`. It sizes each pool of warm pods from the rate of claims, deletes the pods that are old or idle or stuck or failed, writes the condition `WarmPodsFailing` on the pool ReplicaSet, and deletes the saves, records and tombstones that have expired. The package has a library and a binary. The binary loads the configuration and runs the library until it gets the stop signal.

## Install

```toml
br-sandbox-keeper = { git = "https://github.com/BotResources/br-jobs-runner-kit", package = "br-sandbox-keeper", tag = "br-sandbox-keeper/v0.1.1", version = "0.1.1" }
```

The crate takes the names of the labels, the annotations, the pool condition and the store keys from `br-runner-sandbox`, and a crate that names the types of that sibling must reach it through the same git url and the same tag string. The image `ghcr.io/botresources/br-sandbox-keeper` holds the binary and the system root certificates, and its tag is the version of the crate.

## Run

The binary reads one JSON document at the path in the variable `BR_SANDBOX_CONFIG`, and the credential of the object store from the variables `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`. The credential is not part of the document, is never logged, and is not shown by `Debug`. The keeper reads no Secret through the Kubernetes API. The logs are JSON lines on the standard output; they hold the keys of objects and the names of pods, never the content of an object. The binary ends with a failure code when the library returns an error, and with the code 0 after SIGTERM or an interrupt.

The binary runs as 2 replicas. The identity of a replica for the Lease is its `HOSTNAME` with a unique suffix. The Lease namespace is `lease_namespace`, or the namespace of the pod when the key is not set.

## Public surface

The library has three parts, and they are the intended entry points: the configuration, the pure rules and the runner. The other public items are the library surface that the three parts are built from: the seams (`bucket`, `cluster`), the read model (`facts`) and the items that the binary reads from its environment. The binary adds nothing to the three parts. The standard derives (`Debug`, and `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash` on the types that have them) are not named type by type, and the table names every other public item.

## Configuration

| Key | Meaning | Default |
|---|---|---|
| `label_prefix` | prefix of the labels and annotations (the value of the adapter) | `br.sandbox` |
| `managed_namespace_selector` | label selector of the namespaces that the keeper serves | `{label_prefix}/managed=true` |
| `store_bucket`, `store_endpoint`, `store_region`, `store_path_style` | the object store (S3 API) | required; `store_path_style` false |
| `listen_address` | address of `/livez`, `/readyz` and `/metrics` | required |
| `save_ttl_seconds` | age after which a save is expired | required |
| `skew_margin_seconds` | extra wait before the keeper deletes an expired save | 60 |
| `sweep_interval_seconds`, `sweep_page_size` | the pass over the store | 60, 1000 |
| `attempt_ttl_seconds` | age of an orphan attempt | 3600 |
| `tombstone_ttl_seconds` | age of a record or tombstone | 31 536 000 |
| `stuck_ttl_seconds` | cap on the age of a dirty claimed pod | 7200 |
| `failed_pod_ttl_seconds` | age of a Failed or Evicted pod | 300 |
| `warm_max_age_seconds` | maximum age of a warm pod | 1800 |
| `pending_alarm_seconds` | time that a warm pod may stay Pending before the event | 60 |
| `rate_window_seconds`, `rate_bucket_seconds` | the window of the claim rate and the width of its buckets | 300, 10 |
| `scale_down_cooldown_seconds`, `scale_down_step`, `scale_down_step_interval_seconds` | damping of a scale-down | 120, 5, 10 |
| `lease_namespace`, `lease_duration_seconds`, `renew_deadline_seconds`, `retry_period_seconds` | leader election | namespace of the pod, 15, 10, 2 |
| `timezone` | time zone name of the floors of the day | `UTC` |
| `pools` | the list of pools; each entry holds the per-pool keys below | required, not empty |
| per pool: `id`, `namespace`, `replicaset`, `min_replicas`, `max_replicas` | the pool | required |
| per pool: `refill_seconds`, `margin` | the sizing rule | 3, 2 |
| per pool: `floors` | windows `{from, to, floor}` of the day; `to` may be `24:00` | none |
| per pool: `idle_ttl_seconds` | how long a saved pod stays bound when its state is not smaller than the threshold | 120 |
| per pool: `idle_keep_min_state_bytes` | the threshold of the state size | 10 000 000 |

A document is a fault when `save_ttl_seconds` is 0 or below; a duration that drives a timer is 0 (except `idle_ttl_seconds` and `skew_margin_seconds`); `min_replicas` is above `max_replicas`; `rate_bucket_seconds` is above `rate_window_seconds`; `scale_down_step` is below 1; the Lease durations are not in the order `lease_duration_seconds` above `renew_deadline_seconds` above `retry_period_seconds`; the time zone is unknown; a window ends no later than it begins; two pools have the same id or the same ReplicaSet in one namespace; a required key is missing; or a key is unknown. The code also refuses: an empty `pools` list; a number below 0, or too large for its type; a text key that is blank; a `store_endpoint` that is not an http or https URL with a host and no user information; a `listen_address` that is not a socket address; a `label_prefix` that `br-runner-sandbox` refuses; and, in a window of `floors`, a `from` or `to` that is not `HH:MM` or `HH:MM:SS` with two digits for each part, with hours below 24 and minutes and seconds below 60 (`to` alone may be `24:00`).

## Labels and annotations

The keeper reads these names through the label prefix and takes them from `br-runner-sandbox`. It never writes a label or an annotation, never claims a pod, and never patches a pod.

| Role | Name | Kind | Use |
|---|---|---|---|
| pool state | `{label_prefix}/pool` = `warm` or `claimed` | pod label | which pods are warm or claimed; the claim rate |
| pool id | `{label_prefix}/pool-id` | pod label | the pool of a pod |
| thread, agent | `{label_prefix}/thread`, `{label_prefix}/agent` | pod labels | log fields only |
| clean or dirty | `{label_prefix}/clean` | pod annotation | idle or stuck |
| claimed-at | `{label_prefix}/claimed-at` | pod annotation | the clock of `stuck_ttl_seconds` |
| idle-since | `{label_prefix}/idle-since` | pod annotation | the clock of the idle deadline |
| state-bytes | `{label_prefix}/state-bytes` | pod annotation | the choice of `idle_ttl_seconds` or 0 |
| managed namespace | `{label_prefix}/managed` = `true` | namespace label | which namespaces the keeper serves |

The keeper serves every namespace that matches `managed_namespace_selector`: it lists them at the start, and again every `sweep_interval_seconds`, and watches the pods of each one. A namespace that no longer matches is not served from the next listing: its watch ends, its pods are forgotten, and nothing is written there until it matches again. It acts only on pods that carry the pool-state label with the value `warm` or `claimed`. A pod of a pool that is not in the configuration (or with no pool id) expires by the same rules, with the default `idle_ttl_seconds` and `idle_keep_min_state_bytes`; it gets no sizing, no condition and no event, because the keeper knows no ReplicaSet for it. A configured pool whose namespace does not match is a fault at the start.

A claimed pod whose annotation that its rule needs is missing or unreadable is never deleted by that rule. It is logged and counted in `br_sandbox_keeper_unreadable_pods`.

## Behaviour

- **Pool size.** `desired = clamp( max( ceil(peak_claim_rate × refill_seconds) + margin, floor_now ), min_replicas, max_replicas )`, in integer arithmetic. The peak claim rate is the highest bucket of `rate_bucket_seconds` in the last `rate_window_seconds`. A claim is a pod that changes from `warm` to `claimed`, or a pod that appears already `claimed` with no owner and is not older than the window. Each replica counts the claims from its own watch. A scale-up is applied at once. A scale-down is applied only after `desired` has stayed below the replicas for `scale_down_cooldown_seconds`, then by at most `scale_down_step` each `scale_down_step_interval_seconds`. The keeper writes `spec.replicas` by server-side apply under the field manager `br-sandbox-keeper`, only when the value differs, and raises `PoolAtMax` once for each transition into a size above `max_replicas`. The chart must not render `spec.replicas`.
- **Pod expiry.** One rule for each state, as a pure function of the pod: a warm pod at `creationTimestamp + warm_max_age_seconds`; a clean claimed pod at `idle-since + ttl` (`idle_ttl_seconds` when `state-bytes` is not below the threshold, 0 below it); a clean claimed pod with no `idle-since`, and a dirty claimed pod, at `claimed-at + stuck_ttl_seconds`; a Failed pod `failed_pod_ttl_seconds` after the keeper first saw it so. A warm pod that is Pending and not failing raises `WarmPodsPending` once for each pod after `pending_alarm_seconds`. A delete carries the uid and the resourceVersion of the last read; on a conflict the pod is read again and judged again, and a pod that is gone is not an error.
- **Failing pool.** The condition `WarmPodsFailing` on the status of the pool ReplicaSet is `True` when a warm pod that has not been Ready (as far as the memory of the replica goes, see "Not guaranteed") has a container with a pull failure (`ImagePullFailing`) or a crash at start (`StartCrashing`), and `False` otherwise, with the reason `NoWarmPodFailing` and an empty message; it is written `False` at the first judgement. `lastTransitionTime` changes only when the status changes.
- **Saves.** Every `sweep_interval_seconds` the leader lists `saves/` in pages of `sweep_page_size` and reads the `made_at` of each manifest. A save is expired when `now - made_at` is above `save_ttl_seconds + skew_margin_seconds`. For one expired save the order is: write the tombstone (`expired_at = made_at + save_ttl_seconds`, a pure function of the manifest), delete the manifest, delete the parts of every attempt, leave the record. An attempt that no manifest names is an orphan once its newest object is older than `attempt_ttl_seconds`. A record or tombstone is deleted when `tombstone_ttl_seconds` has passed since its end time (its start time when it has no end time) or, for a tombstone, since its `expired_at`; the time that the store gives an object never decides. The sweep lists `records/` and `tombstones/` and reads every listed object on every sweep, as it reads every manifest. An object that cannot be read, or that holds no readable time, is never deleted for age; it is logged with its key and counted in `br_sandbox_keeper_sweep_errors_total`. The keeper writes only under `tombstones/`, and `GuardedBucket` refuses any other write or any key outside `saves/`, `records/` and `tombstones/`.
- **Pod watch.** The keeper lists the pods of a namespace, then watches them from the version of the list. A list that fails, a watch that cannot be opened or reopened, a watch that breaks and an error event of the watch each give a log line at the error level with the namespace and the reason, and count once in `br_sandbox_keeper_sweep_errors_total`. The keeper then waits one second and lists again, so the next event or list repairs the pod view. A watch that ends with no error is reopened with no log line and no count. A failed pod watch does not change `/readyz` after the first sync: the keeper keeps the pods it has and acts on them until the next list succeeds.
- **Leader election.** A Lease named `br-sandbox-keeper`. Both replicas keep their watches; only the holder writes (replicas, condition, events, pod deletes, tombstones, object deletes). A write is refused once `renew_deadline_seconds` has passed without a renewal.
- **Endpoints.** `/livez` answers 200 while the process runs. `/readyz` answers 503 until every watched namespace has done its first full sync, and while the store check of the start has not passed. `/metrics` answers in the Prometheus text format: `br_sandbox_keeper_pool_desired`, `_pool_warm_ready` and `_claims_per_second` (each with the label `pool`, one series for each configured pool), `_idle_pods` (no label: the number of claimed pods whose clean annotation is `true`, in every managed namespace, whether their pool is configured or not), `_pods_deleted_total` (label `reason`: `warm_max_age`, `idle`, `stuck`, `failed`), `_saves_deleted_total`, `_tombstones_written_total`, `_orphans_deleted_total`, `_sweep_errors_total`, `_unreadable_pods`, `_is_leader`. The events are `PoolAtMax` and `WarmPodsPending`, on the ReplicaSet of the pool.

## Rights

In each managed namespace: `pods` get, list, watch, delete; `replicasets` get, list, watch, patch; `replicasets/status` patch; `events` create. In the Lease namespace: `leases` get, create, update. Cluster-wide: `namespaces` get, list, watch. No `pods/exec`, no `pods/patch`, no `secrets`. In the store: read and delete on `saves/`, `records/` and `tombstones/`, write on `tombstones/` only. The keeper calls only the API server and the store. The client of the store and the client of the API server use the verifier of the system (`rustls-platform-verifier`, which reads the system root certificates), and the dependency tree has no `webpki-roots`. In a pod the configuration of the API client holds the CA certificate that the service account mounts, and `kube` verifies the API server with that certificate alone; it falls back to the system roots only when the configuration holds none. That behaviour of `kube` is the documented behaviour of the dependency, and no test of this crate checks it: the lock file proves only which TLS crates are in the dependency tree, and no test refuses a bad certificate in a handshake.

## Not guaranteed

- A namespace that gets the managed label after the start is watched from the next discovery (`sweep_interval_seconds`), and one that loses it is dropped at the next discovery; between the change of the label and the discovery the keeper still serves it.
- "Has not yet been Ready" is what a replica saw on its own watch. No field of a pod object says that the pod was Ready once, and the keeper does not guess it from timestamps. After a restart of a replica, a warm pod that was Ready earlier and is now not Ready with a container in `CrashLoopBackOff` is judged as never Ready: the pool goes `True` with the reason `StartCrashing` until that pod becomes Ready, is deleted at `warm_max_age_seconds`, or is seen Ready by the replica.
- The events `PoolAtMax` and `WarmPodsPending` are raised once for each transition or pod in the memory of a replica: a new leader or a restart may raise one again.
- A pool is judged only after the first full sync of its namespace; until then its replicas and its condition stay as written.
- With no keeper running no save is deleted and no pool is resized.
- The keeper applies `spec.replicas` and the condition `WarmPodsFailing` by server-side apply with `force`. A field that another field manager holds is taken over with no conflict, no log and no event. A chart that renders `spec.replicas` is overwritten by the keeper, and nothing reports it.
- No test proves that the keeper opens no connection other than to the API server and the store (no other service, no vendor, no telemetry, no licence endpoint). The rights test fixes the calls to the API server, and a CI gate checks that the crate has no bus access. The code holds no other client, but a dependency that opens a connection would not fail a test.
- A crash between the delete of the manifest and the delete of a part leaves that part to the orphan rule, because the next sweep finds no manifest. The part goes at the first sweep after its newest object is older than `attempt_ttl_seconds`, and not at the next sweep when it is younger than that. A part is written at or before `made_at`, so when `save_ttl_seconds` is above `attempt_ttl_seconds` (3600 by default) the part is already older than `attempt_ttl_seconds` once the save is expired, and the next sweep removes it. When `attempt_ttl_seconds` is the larger of the two, the part stays until it is that old.
- The manifest of every listed save, and every listed record and tombstone, is read on every sweep, and its age comes only from its content.
- The pool size follows the claim rate with the lag of one bucket (`rate_bucket_seconds`) for a change that is not caused by a pod event, because the controller evaluates the pools at each bucket.

## Why

| Thing | Why it is the way it is |
|---|---|
| Each replica counts claims from its own watch | A change of leader loses no rate; a cold start gives the floor |
| The tombstone has no skew margin | The adapter's read-side check fires first; the tombstone is the same bytes whenever it is written, so no conditional write is needed |
| The tombstone is written before the manifest is deleted | The adapter never meets "record done, no manifest, no tombstone" for a save that the keeper expired |
| The manifest is deleted before the parts | No half of a save is ever visible |
| `GuardedBucket` wraps the store client | The rule "writes only under `tombstones/`" is enforced by one type, not by the care of each call |
| A failed action counts in `sweep_errors_total` | The metrics list has no other error counter; the action is tried again at the next event or pass |
| `/readyz` reflects only the start checks and the first sync | A lost API or store at run time is logged and counted; the replica stays up and tries again |
| The time zone database is embedded (`jiff` with `tzdb-bundle-always`) | The image has no zoneinfo files; the zone of the floors of the day must resolve by name with no file |
| `reqwest` is declared and no line names it (`cargo-machete` ignores it) | It fixes the TLS features of the HTTP client of `object_store`: rustls with the system roots and no bundled provider. The crate installs `ring` itself, and the tree has no `webpki-roots` |
| A pool is judged only after the first sync of its namespace | A new leader that judged the pool before it had seen the pods would write `False` over a `True` of the previous leader |
| The keeper remembers that a pod was Ready | The pod object says only whether it is Ready now; a pod that crashes after it served is not an image failure. The memory is lost at a restart (see "Not guaranteed") |
| Every record and tombstone is read on every sweep | The sentence of the intent counts from the end, the start or `expired_at`, which only the content holds. A tombstone is written at the sweep, which can be much later than `expired_at` after a long stop, so the store time can only delay a delete |
| The document that the chart renders is proved by the real type | `tests/chart_config.rs` renders `charts/br-sandbox-chart` with `helm template` for each values file of the chart CI that enables the keeper, and loads the ConfigMap key through `KeeperConfig::from_json`; a key that the chart renders and the keeper does not know fails that test. `tests/chart_values.rs` renders the file `ci/keeper-nondefault-values.yaml`, which sets each mapped value away from its default, and compares every value of the typed config with it. The tests need `helm` and fail without it |
| The logs are proved by running the binary | `tests/binary.rs` starts the real binary with no configuration and parses every line it writes as a JSON object |
| The TLS roots are proved by the lock tree | `kube-client` and `reqwest` (the client of the store) each depend on `rustls-platform-verifier`, and no `webpki-roots` is in the tree; a handshake test would need a private key in the repository |
| A namespace is served through a token that its watch stops on | The watch of a namespace that loses the label ends at the next discovery, with its pods, its claim window and its sizing state, so no write follows |
| A pod of a pool that is not configured gets the default pool values | The keeper acts on every pod with the pool-state label and a pod must not stay for want of a pool entry |
| `idle_pods` has no label | The sealed metric list gives the label `pool` to three metrics only; the gauge counts every claimed clean pod that the keeper watches, so a pod of a pool that is not configured is counted |
| Pools are evaluated at each rate bucket as well as on events | The floor of the day and the sliding window change `desired` with no pod event |
